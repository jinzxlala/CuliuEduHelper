# CuliuEduHelper 第二阶段自动化功能测试计划

> 文档状态：已冻结执行计划  
> 测试范围：`docs/dev_plan_stage2.md` 中已经实现的学生画像与课程规划功能  
> 数据范围：仅使用合成学生、课程、教师、地点和反馈材料

## 1. 测试原则与验收口径

- 学生基础信息沿用当前实现的稳定字段契约：`identity.chinese_name`、`identity.english_name`、`education.grade`、`education.school`、`identity.birth_date`、`contact.parent_phone`。
- 参考教学反馈 CSV 只用于确认“公共课程列、每名学生独立反馈列、空白尾列”的结构；不得复制真实姓名、联系方式、课程反馈或其他真实内容。
- 所有模型流程调用真实 DeepSeek：四类基础导入、CSV/DOCX 增量提取、画像生成和课程推荐，共 8 个正常逻辑任务。允许系统现有的有限重试，不允许人工无限重提。
- 测试使用临时 PostgreSQL 数据库、独立 BullMQ 队列和 `tmp/stage2-functional/<run-id>/` 对象目录，不得写入日常开发数据库、正式知识索引或现有学生档案。
- 测试开始前计算本文件 SHA-256。执行期间不得跳步、调换顺序或降低断言；如需改变计划，应停止本轮并重新冻结计划。
- 本轮只验证合成数据技术功能，不替代真实受控学生和真实排课的业务试点。

## 2. 合成文件与隔离环境

在 `tmp/stage2-functional/<run-id>/fixtures/` 生成：

| 文件 | 用途 | 必须覆盖的结构 |
|---|---|---|
| `basic-students.txt` | TXT 基础建档 | 无英文名、五项基础资料 |
| `basic-students.md` | Markdown 基础建档 | 多名学生、兄弟姐妹共用虚构电话 |
| `basic-students.docx` | Word 基础建档 | 段落式家长资料 |
| `basic-students.csv` | CSV 基础建档 | UTF-8 BOM、引号、嵌入换行、空白尾列 |
| `incremental-feedback.csv` | 教学反馈增量提取 | 公共课程列、目标学生列、诱饵学生列、单元格内独立日期/教师/课程 |
| `incremental-meeting.docx` | 家长会议增量提取 | 只属于目标学生的虚构逐字稿 |
| `oversize.txt` | 上传边界 | 大于 20 MB |
| `fixture-manifest.json` | 预期结果 | 文件哈希、字段、来源定位和禁止泄漏哨兵 |

CSV 必须用 `@oai/artifact-tool` 生成并重新导入检查；DOCX 使用确定性生成器创建，并在上传前验证当前解析器能够读取全部正文。测试完成、脱敏结果写入 `AGENTS.md` 后删除整个运行目录。

新增根命令 `pnpm test:functional:stage2`。运行器负责创建临时数据库、应用迁移、创建临时账号与授权、启动独立队列、Web 服务和只处理第二阶段任务的 Worker，完成 HTTP 上传与数据库断言，并在成功或失败后清理资源。浏览器自动化连接同一隔离环境，验证页面点击、文件选择、轮询、审核和导航。

## 3. 严格执行顺序

### S2-00 基线与环境

1. 保存测试前 `git status --short`，不得覆盖既有工作区修改。
2. 确认 Node.js 22、PostgreSQL、Redis 和 DeepSeek 配置可用；只记录“已配置/未配置”，不得输出密钥。
3. 依次运行：

```powershell
pnpm --filter @culiu/student-ingest test
pnpm --filter @culiu/student-profiles test
pnpm --filter @culiu/course-planning test
pnpm --filter @culiu/web test
pnpm test:integration
```

### S2-01 合成文件生成

1. 生成七个上传文件及 `fixture-manifest.json`。
2. 复验文件 SHA-256、大小、UTF-8/BOM、CSV 独立学生列、嵌入换行与空白尾列。
3. 扫描全部夹具，确认不包含参考文件中的真实姓名、联系方式或反馈。
4. 用当前 DOCX 解析器读取两个 Word 文件并核对完整正文。

### S2-02 隔离运行环境与权限

1. 创建随机临时数据库、对象目录、队列、管理员账号和顾问账号；顾问只获得指定合成学生授权。
2. 验证未登录访问学生 API 返回 401，无权限或跨学生访问统一返回 404。
3. 验证顾问不能批量建档、维护课程模板、维护排课资源或运行排课。
4. 验证顶部导航可闭环进入学生、批量导入、课程模板和排课页面。
5. 验证业务页面不要求用户编辑 JSON、数据库字段或内部 UUID。

### S2-03 四类基础信息批量导入

1. 按 TXT、Markdown、DOCX、CSV 顺序通过页面上传。
2. 每个批次必须经历 `uploaded → processing → review_ready`，并保存安全任务状态。
3. 校验 DeepSeek 结构、来源定位、虚构电话占位与还原、无英文名、重复候选和共享电话提示。
4. 覆盖字段值修改、创建、拒绝、关联已有学生、逐字段接受/拒绝以及重复决定幂等。
5. 未确认候选不得创建学生；接受字段必须形成版本化事实和合法派生证据。

### S2-04 增量画像更新

1. 上传合成教学反馈 CSV，确认只截取目标学生列；诱饵学生姓名和反馈不得进入模型输入、建议、日志或审计。
2. 上传合成会议 DOCX，验证归属确认和目标学生身份定位。
3. 覆盖字段键和值修改、逐条接受/拒绝、整组接受/拒绝、过期页面并发冲突和重复决定。
4. 接受建议必须生成不可变证据、具体定位和线性事实版本；拒绝建议不得修改正式事实。

### S2-05 学生画像联动

1. 使用接受后的事实手动发起真实 DeepSeek 画像草稿。
2. 验证八部分结构、证据引用、脱敏、人工修改、提交、批准和审核历史。
3. 接受新的增量事实后，已批准画像必须变为 `needs_review`，且不会自动重新生成。
4. 停止 Worker 后，验证手动事实维护和画像人工编辑仍可使用。

### S2-06 课程模板、班级与推荐

1. 使用业务表单创建、批准、修订和归档课程模板，确认旧版本不可覆盖。
2. 创建并批准教师、固定地点、实际班级和多套完整候选课表。
3. 验证班级只能选择已批准课程和地点，文本学生名单不建立学生关联。
4. 基于批准画像运行真实 DeepSeek 推荐，验证只返回冻结集合内的课程、班级和 claim ID。
5. 覆盖无可选班级、替代路径、接受/拒绝和带入人工规划。
6. 未批准或 `needs_review` 画像不得生成推荐。

### S2-07 教师分配与整数规划排课

1. 运行“班级—教师—完整候选课表”求解。
2. 覆盖教师资质、允许教师范围、教师/地点冲突、不可用日期、每日/每周课时、周课展开、短期营、业务优先级、偏好惩罚和锁定课表。
3. 验证地点保持固定、教师由求解器选择，文本学生名单不参与冲突检测。
4. 覆盖 `solved`、`partially_solved`、`infeasible` 和安全未排原因。
5. 相同输入重复求解必须得到相同结果哈希；只有管理员批准后才成为正式课表。

### S2-08 失效传播、安全与边界

1. 使已接受事实的证据失效，验证画像、推荐和规划进入 `needs_review`。
2. 扫描 API 响应、队列、Web/Worker 日志和审计，禁止出现虚构电话、邮箱、诱饵学生反馈、模型原始响应或服务密钥。
3. 验证空文件、错误格式、歧义学生列、超过 20 MB、缺少身份事实、非法状态转换和跨学生参数替换。
4. 失败任务不得覆盖已批准画像、规划或课表。

### S2-09 全量回归与清理

1. 依次运行：

```powershell
pnpm test:integration
pnpm check
git diff --check
```

2. 停止隔离 Web/Worker、清空测试队列、删除临时数据库和 `tmp/stage2-functional/<run-id>/`。
3. 确认测试前已有修改仍存在，模拟数据、临时凭据和模型内容未进入 Git。

## 4. 失败处理与记录

任何用例失败后立即停止后续编号：

1. 在 `AGENTS.md` 记录编号、时间、期望、实际、安全日志摘要和复现步骤；
2. 定位根因并实施最小修复；
3. 运行对应单元测试和集成测试；
4. 从干净隔离环境重新运行失败用例；
5. 重跑该阶段此前通过的关键用例；
6. 记录根因、修改文件、验证命令和最终结果后继续下一编号。

`AGENTS.md` 的测试记录必须包含各阶段状态、真实 DeepSeek 逻辑任务数、重试数、Token 用量与成本估算、缺陷修复和剩余业务门禁；不得记录服务密钥、完整模型输入或原始响应。

已知重点验证项为“关联已有学生”和“整组接受/拒绝建议”。如果当前页面或接口不能完成，对应用例必须判定失败并按本节修复，不得通过降低验收标准绕过。

## 5. 完成标准

- S2-00 至 S2-09 按顺序全部通过，所有失败均有修复和重测记录；
- 未审核模型结果写入正式事实次数为 0；
- 跨学生内容进入模型输入或事实建议次数为 0；
- 接受事实的合法证据定位率为 100%；
- 推荐集合外 ID、教师资质违规、教师冲突和地点冲突均为 0；
- 相同排课输入得到相同结果哈希；
- 临时数据库、队列、对象目录和账号全部清理；
- 最终结论只能是“合成数据技术功能测试通过”，不得替代真实业务验收。
