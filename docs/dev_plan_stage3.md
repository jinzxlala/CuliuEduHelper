# CuliuEduHelper 第三阶段开发计划：智能搜索与智能分析

> 文档状态：已确认开发计划
>
> 更新日期：2026-08-05
> 开发方式：1 名项目负责人，与 Codex、Claude Code 等 Code Agent 协作

## 1. 阶段目标

在现有关键词搜索、48 场讲座和 184 张匿名案例基础上，形成以下闭环：

`自然语言需求 → 混合召回 → DeepSeek 筛选重排 → 加入分析工作区 → 多对话分析 → 生成可视化 HTML 报告`

已确认产品决策：

- 分析工作区可显式共享给指定内部账号；
- 工作区资料冻结原版本，知识库出现新版本时提示使用者主动更新；
- 对话和报告仅使用当前对话及工作区资料，不自动读取同一工作区的其他对话。

本阶段交付：

- 保留现有关键词搜索，新增独立的智能搜索模式；
- 直接加入中文向量与关键词混合检索；
- 建立受限、可追踪的智能搜索 Agent，而非开放式自主 Agent；
- 支持创建、归档和显式分享分析工作区；
- 支持从所有讲座、案例搜索结果批量加入工作区；
- 每个工作区支持多个互相隔离的对话；
- 支持基于当前对话生成带简单内部控件的单页 HTML 分析报告；
- 支持预览、下载受控交互版 HTML，并同时提供无脚本的静态归档版；
- 保存模型、提示词、知识版本、Token、成本、引用和任务状态；
- 不把对话或分析产物自动写回正式知识库。

明确不包含：

- 学生档案或教务数据进入知识分析；
- 家长账号或公开分享链接；
- 开放式工具调用、自动联网或任意 SQL；
- 模型生成 JavaScript；
- 自动把分析结论发布为讲座或案例事实；
- PDF、PPT、DOCX 报告导出。

## 3. 智能搜索

### 3.1 中文混合检索

在现有 `lectures` 和 `cases` 索引中配置本地 Hugging Face embedder：

- 模型：`BAAI/bge-small-zh-v1.5`；
- 512 维、24M 参数，适合当前中文小规模知识库；
- embedder 名称固定为 `knowledge_zh_v1`；
- 使用成功验收时解析出的 Hugging Face commit SHA 固定模型 revision；
- 使用 Meilisearch 本地运行模型，不新增外部嵌入供应商；
- 讲座和案例分别使用字段化 `documentTemplate`；
- 保留纯关键词查询，嵌入服务异常时不得影响原搜索功能。

Meilisearch 支持本地 Hugging Face embedder、模型 revision 固定和关键词/语义混合搜索。参考：<https://www.meilisearch.com/docs/capabilities/hybrid_search/how_to/configure_huggingface_embedder>。

`BAAI/bge-small-zh-v1.5` 是面向中文检索的轻量模型。参考：<https://huggingface.co/BAAI/bge-small-zh-v1.5>。

在智能搜索金标集上比较 `0.25`、`0.5`、`0.75` 三档语义权重，选择最终值，不凭经验固定。索引重建、嵌入失败或内存不足时，旧索引继续提供服务。

讲座的嵌入文本包括标题、摘要、趋势、AI/跨学科、失败风险、机构、学校和专业。案例的嵌入文本包括案例概览、核实事实、背景、发展路径、核心项目、优势、申请策略、顾问启示、专业、学校和活动/研究/AI标签。嵌入模板不得包含原始逐字稿正文或受隐私门禁保护的内容。

### 3.2 有界 Agent 工作流

每次智能搜索运行固定为以下步骤：

1. 用户输入不超过 1,000 字的自然语言搜索要求；
2. DeepSeek 返回严格 JSON 查询计划；
3. 服务端校验目标索引、关键词、匹配模式和筛选字段；
4. 最多执行 6 个查询计划，每个计划召回最多 20 条；
5. 同时使用关键词和混合检索，合并后最多保留 60 个候选；
6. DeepSeek 只能在候选 ID 集合中筛选、重排和解释；
7. 最终返回最多 20 条讲座或案例；
8. 结果显示匹配原因、相关字段、可信度和可点击来源；
9. 首轮结果不足时允许再规划一次，总检索轮次最多为 2。

模型不能：

- 自己连接 Meilisearch；
- 创造讲座、案例或筛选字段；
- 修改服务端权限和搜索范围；
- 返回候选集合之外的 ID；
- 把分析性判断伪装为逐字稿直接证据。

运行状态：

`queued → planning → retrieving → reranking → succeeded/failed`

每次运行保存查询计划、候选 ID、最终排序、知识批次、模型版本、提示词和 Schema 哈希、Token、成本、耗时及安全错误码，但不保存 DeepSeek 原始响应。

### 3.3 智能搜索结果页面

新增 `/smart-search` 页面，与 `/search` 的普通关键词搜索并列：

- 显示系统对用户意图的结构化理解；
- 显示实际采用的搜索范围和筛选条件；
- 每条结果显示智能排序理由和合法引用；
- 支持打开讲座或案例详情；
- 支持单条或批量加入分析工作区；
- 任务执行期间通过状态轮询显示规划、召回和重排进度；
- DeepSeek 不可用时提示使用普通关键词搜索，不伪装为智能搜索成功。

## 4. 分析工作区与对话

### 4.1 工作区权限

工作区默认为创建者所有，并支持显式分享给现有内部账号：

- `owner`：管理名称、成员、资料、对话、报告和归档；
- `editor`：添加资料、创建对话、发送消息和生成报告；
- `viewer`：只读查看、预览和下载；
- 审计员即使被分享也只能作为 `viewer`；
- 服务账号不能成为工作区成员；
- 管理员不会因为角色自动获得所有工作区正文权限；
- 未授权或跨工作区访问统一返回 404。

第一版只支持归档，不提供永久删除，避免破坏模型运行和报告引用。停用账号、撤销分享或归档工作区后，既有会话必须立即失效或失去对应访问权。

### 4.2 知识版本冻结

加入工作区时保存：

- 当前知识批次 ID；
- 资料类型；
- 讲座或案例 ID；
- 内容版本哈希；
- 添加人和添加时间。

知识库重新导入后：

- 已有工作区继续使用原版本；
- 页面显示“存在新版本”；
- 用户主动更新时创建新的工作区资料版本；
- 已完成的对话和报告继续引用原版本，不被覆盖。

工作区资料从 PostgreSQL 的版本化知识表读取，Meilisearch 只用于发现和召回。工作区资料更新采用追加版本，不原地覆盖旧引用。

### 4.3 页面流程

新增：

- `/analysis`：工作区目录；
- `/analysis/[workspaceId]`：资料、对话、成员与报告；
- `/analysis/[workspaceId]/conversations/[conversationId]`：对话页面。

关键词搜索、智能搜索和讲座/案例详情页均增加：

- 单条“添加到工作区”；
- 多选复选框；
- “批量加入所选资料”；
- 当前工作区选择器；
- 内联创建新工作区。

每个工作区最多保存 100 项资料和 50 个对话；达到限制时明确提示，不静默截断。重复加入同一知识版本应返回已有关系，不产生重复资料。

### 4.4 多对话与分层上下文

同一工作区可以建立多个对话，但各对话历史互相隔离。每次模型请求包含：

- 当前对话历史；
- 工作区全部资料的紧凑目录；
- 与当前问题最相关资料的完整结构化正文；
- 模型和引用规则。

上下文策略：

- 完整资料不超过约 12 万 Token 时全部展开；
- 超出后，为所有资料提供最多 800 字的紧凑摘要；
- 通过混合检索展开最相关的最多 20 项完整资料；
- 对话历史较短时全部发送；
- 长对话使用“旧消息版本化摘要＋最近 12 条完整消息”；
- 单次模型输入设置 20 万 Token 的内部成本上限；
- 上下文序列化顺序保持稳定，便于利用供应商上下文缓存；
- Token 估算使用服务端保守估算，并根据实际 provider usage 持续校准。

DeepSeek 当前模型支持更大的上下文，但系统仍主动限制输入，避免成本和失败随工作区无限增长。参考：<https://api-docs.deepseek.com/quick_start/pricing/>。

模型回答采用严格 JSON：

- `answerMarkdown`；
- `citations`；
- `uncertainties`；
- `suggestedFollowUps`。

所有引用必须属于当前工作区冻结资料；无法从资料支持的判断必须标记为“分析性判断”或“待核实”。正文按安全 Markdown 渲染，不允许模型直接返回可执行 HTML。

## 5. 可视化分析报告

### 5.1 任务输入

报告任务只能从某一个当前对话发起，输入冻结：

- 当前工作区资料版本；
- 当前对话截至发起时的全部历史；
- 用户填写的分析要求与限制；
- 模型、提示词、Schema、知识批次和代码版本。

用户不填写要求时，使用默认框架：

- 资料范围和样本量；
- 讲座年份与主题趋势；
- 案例类型、专业、学校和课程体系分布；
- 科研、活动、AI 及核心项目标签；
- 可信度和证据缺口；
- 主要趋势、反例与数据限制。

报告只使用发起任务的当前对话，不自动读取同一工作区中的其他对话。

### 5.2 统计和生成流程

不允许模型直接计算最终比例：

1. DeepSeek 生成结构化分析计划；
2. 服务端校验允许的字段、分组、筛选和统计操作；
3. TypeScript 代码执行计数、比例、分组和时间序列计算；
4. 语义分类任务只能返回来源 ID 和分类标签；
5. 服务端重新计算分类数量和比例；
6. DeepSeek 根据已计算数据和合法引用生成结构化报告内容与图表配置，不生成脚本；
7. 服务端使用固定、版本化的 HTML/CSS/JavaScript 模板渲染交互版，并使用无脚本模板渲染静态归档版；
8. 两个版本均通过安全解析、允许列表和引用校验后才保存。

允许的确定性统计操作首期限定为：

- `count`；
- `group_count`；
- `ratio`；
- `timeseries`；
- 基于白名单字段的等值/集合筛选。

模型不能生成或执行 SQL、JavaScript、Python 或其他代码，也不能自行选择工作区外的数据。交互能力完全由系统维护的固定模板提供，模型只能输出服务端 Schema 允许的内容、图表和交互目标 ID。这样可以避免算术错误、分母不一致、创造样本或注入可执行内容。

### 5.3 固定交互控件

交互版报告首期提供以下页面内能力：

- `75%—200%` 分级放大、缩小和恢复默认比例；
- 点击图表、卡片或正文区块后突出显示，其他内容弱化；
- 展开或收起章节；
- 页面内搜索并高亮关键词；
- 专注模式；
- 点击图例临时筛选或强调对应数据系列；
- 一键重置全部交互状态。

交互只改变当前页面的查看状态，不修改报告原始数据、统计结果、引用或对象哈希。首期不把查看状态同步到数据库，也不支持用户编写脚本、公式或查询。

### 5.4 HTML 安全边界

每份报告生成两个自包含的单页 HTML 版本：

- **交互版：**包含系统固定、经过审查并带版本号的内联脚本；
- **静态归档版：**不含任何脚本，保留完整正文、图表、统计和引用。

共同安全边界：

- 允许内联 CSS 和受限 SVG 图表；
- 最大 2 MB；
- 禁止模型生成或用户提供 JavaScript；交互版只允许构建产物中固定的系统脚本；
- 禁止内联事件属性、动态代码执行、`eval`、`Function` 和表单；
- 禁止 `iframe`、`object`、`embed`；
- 禁止外链图片、字体、脚本和 CSS；
- 禁止 CSS `url()`、`@import` 和网络请求；
- 预览页面使用隔离 iframe 和严格 CSP，交互版脚本通过固定哈希放行；
- 下载接口使用 `Content-Disposition: attachment`；
- 两个 HTML 版本分别保存到不可变对象存储，数据库只保存路径、哈希、模板版本和元数据。

报告状态：

`queued → planning → computing → rendering → succeeded/failed`

报告生成后不可原地覆盖；重新生成会创建新版本。失败任务不得覆盖既有成功报告。

## 6. 数据模型与接口

### 6.1 新增核心实体

| 实体 | 主要内容 |
|---|---|
| `knowledge_smart_search_run` | 用户提示、状态、知识批次、查询计划、候选/结果引用、版本、用量和安全错误 |
| `knowledge_analysis_workspace` | 创建者、名称、说明、状态和更新时间 |
| `knowledge_analysis_workspace_member` | 工作区成员、`owner/editor/viewer` 权限和授权记录 |
| `knowledge_analysis_source` | 冻结知识批次、资料类型、资料 ID、内容哈希及替代版本关系 |
| `knowledge_analysis_conversation` | 工作区、标题、状态和消息序列 |
| `knowledge_analysis_message` | 用户/助手消息、顺序、Markdown 正文、合法引用和关联运行 |
| `knowledge_agent_run` | 搜索、对话和报告模型步骤的输入快照、版本、状态、Token、成本和失败摘要 |
| `knowledge_analysis_report` | 当前对话快照、用户要求、结构化报告、交互/静态 HTML 对象、各自哈希、模板版本、预览信息和生成状态 |

消息、成功的模型输出、知识引用和报告对象采用追加写入；更正通过新消息、新运行或新报告完成，不原地改写历史记录。

### 6.2 主要 API

- `POST /api/knowledge/smart-search/runs`；
- `GET /api/knowledge/smart-search/runs/:runId`；
- `GET/POST /api/knowledge/analysis/workspaces`；
- `GET/PATCH /api/knowledge/analysis/workspaces/:workspaceId`；
- `PUT/DELETE /api/knowledge/analysis/workspaces/:workspaceId/members/:userId`；
- `POST/DELETE /api/knowledge/analysis/workspaces/:workspaceId/sources`；
- `GET/POST /api/knowledge/analysis/workspaces/:workspaceId/conversations`；
- `POST /api/knowledge/analysis/workspaces/:workspaceId/conversations/:conversationId/messages`；
- `POST /api/knowledge/analysis/workspaces/:workspaceId/conversations/:conversationId/reports`；
- `GET /api/knowledge/analysis/reports/:reportId`；
- `GET /api/knowledge/analysis/reports/:reportId/download?mode=interactive|static`。

所有接口要求有效知识系统会话，响应使用 `private, no-store`。跨用户、跨工作区和未分享资源统一返回 404。浏览器不得接收 Meilisearch、DeepSeek、数据库或对象存储密钥。

### 6.3 Worker 任务

新增：

- `knowledge.smart-search`；
- `knowledge.analysis.chat`；
- `knowledge.analysis.report`。

任务只携带运行 ID、冻结快照 ID/hash、授权上下文和版本信息，不携带完整资料正文或对话正文。Worker 从 PostgreSQL 重新读取冻结输入并复验授权，模型返回的任何工作区、知识或用户 ID 均不得扩大任务权限。

每个任务记录 Git commit、模型、提示词、Schema、上下文构造、嵌入和计价版本。任务有限重试最多 3 次，已成功的模型阶段保存检查点，重试时不得重复计费执行已经成功的阶段。

## 7. 测试和验收

### 7.1 自动化测试

- 查询计划、筛选、循环次数和候选 ID 校验；
- 混合检索、关键词降级、索引原子替换和模型 revision 固定；
- 工作区 `owner/editor/viewer` 权限；
- 跨工作区访问、停用账号和分享撤销；
- 冻结版本、新版本提示和主动更新；
- 多对话历史隔离；
- 分层上下文、长对话摘要和 Token 预算；
- 引用不存在、跨工作区引用和提示词注入；
- BullMQ 幂等、有限重试、阶段检查点和失败恢复；
- 比例、分组、时间序列及分母准确性；
- 模型或用户提供的 HTML 脚本、事件、外链、CSS URL 和危险 SVG 拒绝；
- 固定交互模板的放大缩小、选中强调、折叠、搜索高亮、专注模式、图例筛选和重置；
- CSP 脚本哈希、无网络请求、无动态代码执行及交互前后统计和引用不变；
- 交互版和静态归档版的预览、下载、独立哈希、不可变存储和恢复备份；
- DeepSeek 不可用时普通关键词搜索和工作区只读功能继续可用。

### 7.2 检索评测

- 原 50 条关键词金标继续全部通过；
- 新增至少 30 条自然语言智能搜索金标；
- 金标由 Code Agent 起草，项目负责人逐条批准；
- 候选召回率@30 不低于 90%；
- 最终 Top-5 命中率不低于 85%；
- 关键查询 Top-5 为 100%；
- 硬筛选和禁止命中为 100%；
- 返回 ID 及引用合法率为 100%；
- 混合检索不得降低原关键词金标门禁。

在项目负责人批准智能搜索金标前，只能声明“智能搜索技术评测通过”，不得宣称顾问业务验收完成。

### 7.3 业务试点

至少完成：

- 15—20 次真实顾问智能搜索；
- 5 个工作区；
- 每个工作区至少 2 个独立对话；
- 至少一次指定内部账号分享及撤销；
- 5 份包含已知比例或趋势的 HTML 报告；
- 每份报告核对交互版的放大缩小、选中强调、搜索和重置，并核对静态归档版无需脚本即可完整阅读；
- 人工核对统计值、引用、顾问可用性和遗漏结果。

只有顾问完成上述复核，才能表述为“第三阶段业务试点通过”；模型任务和合成数据测试通过仍只能称为技术验收。

### 7.4 安全与恢复门禁

- API、BullMQ、日志和审计中不出现密钥或 DeepSeek 原始响应；
- 工作区正文和对话正文不复制进审计事件；
- 知识资料中的提示词注入文本不能改变工具、权限和引用集合；
- 模型不能访问机构学生资料或教务系统 API；
- 模型生成的可执行内容为 0，报告外部网络请求为 0；
- 交互版只能运行与记录模板版本匹配、通过固定 CSP 哈希放行的系统脚本；
- 新增表、消息、分享关系和 HTML 对象全部进入加密备份与隔离恢复演练；
- 模型、嵌入或 Worker 故障不得破坏普通搜索和已完成分析产物。

## 8. 输入门禁与默认约定

开发开始前需要准备：

- 至少 30 条自然语言智能搜索查询草案及期望结果；
- 5 个代表性分析任务，包括比例、趋势、对比、反例和开放式总结；
- 可用于分享测试的两个以上虚构内部账号；
- DeepSeek 单次与月度成本上限；
- 本地 Docker 为 Meilisearch 嵌入模型预留的 CPU、内存和首次下载空间；
- 项目负责人对 HTML 标签、CSS、SVG、固定交互控件及静态归档降级范围的最终确认。

默认约定：

- 继续使用 `deepseek-v4-flash` 和现有 JSON 网关；
- 扩展模型接口以支持消息数组，不直接引入供应商 SDK；
- 使用结构化输出，服务端对所有 ID、引用和分析操作复验；
- DeepSeek JSON 模式需要提示词明确要求 JSON，并设置合理输出上限，避免空响应和中途截断。参考：<https://api-docs.deepseek.com/guides/json_mode/>；
- 向量只服务于知识库，不涉及学生资料；
- 不采用通用 Agent 框架、Meilisearch 内置聊天工作区或独立向量数据库；
- 普通关键词搜索在 DeepSeek、Worker 或嵌入模型不可用时仍可使用；
- 模型原始响应、密钥和不必要的完整上下文不得进入日志或审计事件；
- 分析对话和 HTML 报告属于内部工作产物，不是正式知识证据，不自动进入 Meilisearch。
