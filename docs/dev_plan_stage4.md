# 第四阶段：智能搜索意图化重构

## 1. 阶段目标

本阶段重构现有智能搜索模块，使系统先识别用户真实意图，再选择相应的检索、统计或分析流程。重点解决“常见目录型查询被模型结构校验拦截”“搜索结果只能返回有限候选，无法准确表达全部结果”“案例年份定义不清晰”和“需要分析的问题被错误当成普通搜索”等问题。

智能搜索统一支持以下四类搜索意图：

| 搜索意图 | 适用场景 | 执行方式 | 主要输出 |
| --- | --- | --- | --- |
| `semantic_search` | 按主题、概念、跨领域关系或自然语言含义查找资料 | DeepSeek 生成检索计划，系统召回候选，再由 DeepSeek 在候选范围内筛选和解释 | 搜索总结、相关讲座和案例 |
| `catalog_browse` | 浏览某年、某学校、某专业或某类资料的完整目录 | 使用确定性筛选、排序和分页，不允许模型删减符合条件的结果 | 精确总数＋分页、讲座与案例列表 |
| `count` | 询问某类讲座或案例共有多少条 | 使用数据库或搜索索引进行确定性计数，不让模型估算 | 精确总数、分类计数和条件说明 |
| `analysis_required` | 询问比例、趋势、比较、相关性、原因或需要综合判断的问题 | 不在搜索页生成不可靠结论，引导用户把相关资料加入分析工作区后执行分析 | 分流说明、建议的资料范围和进入工作区入口 |

每次成功搜索都应先显示系统对本次需求的解释、实际采用的搜索条件和结果范围，再显示对应讲座与案例。普通用户不需要了解检索计划、索引字段或模型 Schema。

现有工作区能力必须完整保留：单条与批量加入工作区保持不变，同时继续支持批量勾选、全选当前页和服务端去重。

## 2. 智能搜索执行流程

### 2.1 意图识别与检索计划

DeepSeek 首先把用户提示词转换为严格、可验证的搜索计划。计划必须明确：

- 搜索意图；
- 目标资料类型，可为讲座、案例或两者；
- 关键词与可选语义表达；
- 日期、学校、专业、课程体系、案例类型等结构化筛选条件；
- 排序方式；
- 是否需要精确计数或转入分析工作区；
- 给用户看的简短需求解释。

讲座和案例使用各自独立的筛选契约，避免把只属于一种资料的字段错误传给另一种资料。模型输出允许关键词为空：仅按年份、学校、专业或资料类型浏览时，空关键词是合法状态，不能再因为缺少关键词而判定为失败。

系统应对可安全推断的字段缺省进行规范化，并只在模型输出无法验证时执行一次结构修复请求。修复后仍不合法时，返回可理解的阶段性错误，不无限重试。

### 2.2 四类意图的执行策略

#### `semantic_search`

- 适用于“AI 与医疗相关案例”“适合机械方向学生的项目经验”等语义型查询。
- 同时使用关键词召回和已配置的混合检索能力形成候选集。
- 语义搜索最多60条候选和20条结果。
- DeepSeek 只能在系统提供的候选集合中筛选、排序和解释，不得创造资料、引用或内部 ID。
- 结果必须标明匹配理由和实际命中的关键词或条件。
- 该模式只声称“找到相关资料”，不能声称已经返回知识库中的全部符合项。

#### `catalog_browse`

- 适用于“所有 2025 年讲座”“某学校相关的全部案例”等目录型查询。
- 使用确定性的筛选、稳定排序、去重和分页，不经过模型二次删选。
- 返回精确总数＋分页，同时返回讲座数量和案例数量。
- 默认每页20条、最大50条。
- 跨讲座和案例浏览时，使用统一、稳定的排序键，确保前后翻页不重复、不遗漏。
- 当符合条件的数据超过系统可安全遍历的上限时，明确提示无法保证完整精确结果，不以局部结果冒充总数。MVP 上限暂定为 10,000 条。

#### `count`

- 适用于“2025 年共有多少场讲座”“人工智能案例有多少条”等数量问题。
- 计数由系统根据结构化条件确定性完成，DeepSeek 只负责理解问题和组织说明，不参与数字计算。
- 同时检索两类资料时，返回总数、讲座数和案例数。
- 计数使用与目录浏览完全相同的过滤规则，保证计数与分页列表一致。

#### `analysis_required`

- 适用于“AI 案例占全部案例的比例”“近两年申请趋势有什么变化”“某类活动是否提高录取概率”等问题。
- 搜索页不得直接用有限候选计算比例、趋势或因果结论。
- 页面说明该请求需要进入分析工作区，并提供创建工作区或选择已有工作区的入口。
- 系统可给出建议资料范围和用于建立工作区的预筛选条件，但最终分析必须基于工作区冻结的资料版本完成。

## 3. 筛选条件与案例日期定义

讲座可使用以下主要筛选条件：日期、机构、讲者、学校、专业。

案例可使用以下主要筛选条件：案例类型、可信度、课程体系、学校、专业、研究方法、活动类型、AI 方向和 AI 深度。

案例年份按来源讲座日期，而不是按案例 ID、录取年份或索引写入时间。为此：

- 案例搜索文档增加可筛选、可排序的 `source_date`；
- `source_date` 从案例绑定的来源讲座当前发布版本中确定性派生；
- 案例详情和结果卡显示“来源讲座日期”，避免用户误认为是学生录取时间；
- 年份查询统一转换为闭区间起点、开区间终点，例如 2025 年转换为 `2025-01-01` 至 `2026-01-01`；
- 既有案例数据通过索引原子重建补齐 `source_date`，不得在正式索引上逐条原地修改形成半更新状态。

## 4. 确定性计数、分页与结果冻结

### 4.1 精确计数

目录浏览和数量查询均由系统读取搜索索引或正式数据库中的确定性结果。模型不得提供、修正或猜测数量。系统应：

- 对同一资料版本去重；
- 分别计算讲座和案例数量；
- 跨类型查询时计算合计；
- 保存实际应用的筛选条件；
- 对上限、索引不可用或数据版本不一致等情况明确标注限制。

### 4.2 分页协议

- 默认每页20条、最大50条；
- 页码从 1 开始；
- 返回总页数、当前页、每页数量、精确总数和当前页范围；
- 分页使用稳定排序和确定性的并列排序字段；
- 用户切换页面后清空页面级勾选，避免把不可见结果误加入工作区；
- “全选”只选择当前页，不隐式选择所有分页结果。

### 4.3 历史结果冻结

智能搜索结果详情表按运行版本冻结以下信息：

- 搜索运行 ID 和结果批次；
- 资料类型、资料 ID、内容版本哈希；
- 展示标题、摘要、来源日期；
- 排序位置、匹配词和匹配理由；
- 搜索意图、实际筛选条件、计数和限制说明。

历史搜索重新打开时从冻结结果读取，不因索引后续更新而改变原结果。用户可以主动重新运行搜索获得新版本。

## 5. 搜索总结与结果页面

### 5.1 搜索总结

搜索总结由系统基于已经验证的搜索计划、实际应用条件和真实计数确定性组装，至少包含：

- 用户希望查找什么；
- 系统识别出的搜索意图；
- 检索了讲座、案例或两者；
- 实际使用的关键词、日期和其他筛选条件；
- 精确总数或语义搜索返回数量；
- 当前页展示范围；
- 结果限制，例如语义搜索只展示最相关的 20 条。

DeepSeek 可以生成面向用户的自然语言描述，但不得改写真实数字、筛选条件和限制信息。

### 5.2 结果卡

每张讲座或案例结果卡显示：

- 可读标题，而不是只显示内部 ID；
- 资料类型；
- 讲座日期或案例来源讲座日期；
- 简短摘要；
- 匹配理由与匹配词；
- 查看来源或详情入口；
- 单条加入工作区按钮；
- 批量选择复选框。

结果页保留现有批量选择模式、全选当前页和统一加入工作区按钮。添加请求继续通过服务端校验权限并按资料类型、资料 ID 和版本去重；已存在于工作区的资料不重复新增，并向用户返回新增数、已存在数和失败数。

## 6. 数据接口与版本兼容

### 6.1 创建搜索

保留现有创建接口：

```http
POST /api/smart-search
Content-Type: application/json

{
  "prompt": "用户的自然语言搜索要求"
}
```

内部升级搜索任务版本、提示词版本、计划 Schema 版本和输出版本。旧客户端仍只需要提交 `prompt`。

### 6.2 获取搜索结果

结果读取接口扩展为：

```http
GET /api/smart-search?id=<search-id>&page=<page>&pageSize=<page-size>
```

响应至少包含：

- `intent`；
- `summary`；
- `appliedConditions`；
- `limitations`；
- `exactTotal`；
- `lectureCount`；
- `caseCount`；
- `page`、`pageSize`、`totalPages`；
- 当前页冻结结果；
- 失败时的安全错误阶段和可公开说明。

### 6.3 旧搜索历史兼容

旧搜索记录继续使用原有 `resultReferences` 展示单页结果，并标注“旧版搜索，仅保留当时前 20 条结果”。旧记录没有完整计数时不得伪造精确总数，也不得在打开历史记录时自动重新搜索。

### 6.4 工作区接口保持稳定

现有单条加入工作区、批量勾选、全选当前页及服务端去重接口保持兼容。智能搜索重构不得删除或弱化 `AddToWorkspaceButton`、批量工作区选择器和服务端授权校验。

## 7. 错误处理与安全边界

错误应区分以下阶段，并给出可操作但不泄露模型原文、密钥或内部堆栈的提示：

- `planning`：意图识别或搜索计划无法通过校验；
- `retrieval`：索引查询、筛选或计数失败；
- `rerank`：语义候选的模型筛选失败；
- `pagination`：冻结结果或分页读取不一致；
- `workspace_handoff`：转入分析工作区失败。

具体要求：

- 纯筛选查询、空关键词查询和只指定资料类型的目录浏览不得被误判为模型结构错误；
- `semantic_search` 的向量或重排能力不可用时，可以安全回退到关键词候选并明确提示；
- `catalog_browse` 和 `count` 不依赖向量模型或 DeepSeek 重排；
- 日志只记录安全错误类型、阶段、版本和运行 ID，不保存 DeepSeek 原始响应或用户资料正文；
- 继续执行账号隔离、搜索历史归属校验、冻结候选白名单、工作区访问授权和资料版本校验；
- 任何失败都不得覆盖已经成功冻结的历史搜索结果。

## 8. 测试与验收

### 8.1 单元测试

覆盖：

- 四类意图的 Schema 和路由；
- 空关键词、纯年份、纯资料类型和多筛选条件；
- 自然语言年份到日期区间转换；
- 案例 `source_date` 派生、筛选和排序；
- 模型安全缺省规范化和一次修复重试；
- 语义候选上限、结果上限和候选白名单；
- 确定性计数、跨类型去重、分页边界和稳定排序；
- 搜索总结不篡改数字和条件；
- 安全错误映射；
- 单条与批量加入工作区保持不变，并继续验证服务端去重。

### 8.2 集成测试

使用真实 PostgreSQL、Redis、Meilisearch 和 Worker 覆盖：

- 讲座、案例及联合查询的精确计数；
- 目录浏览多页遍历无重复、无遗漏；
- 案例年份按来源讲座日期过滤；
- `source_date` 索引原子重建和失败回滚；
- 智能搜索结果批次冻结及历史分页；
- 旧搜索历史兼容；
- 账号间历史搜索隔离；
- 单条加入、批量勾选、全选当前页和服务端去重；
- 分析型请求向工作区安全分流。

### 8.3 五条真实 DeepSeek 验收查询

必须使用真实 DeepSeek 依次验证：

1. `帮我检索所有2025年内的讲座`
2. `帮我检索所有2025年内的讲座和学生案例`
3. `查找AI与医疗相关的讲座和案例`
4. `2025年共有多少场讲座`
5. `AI案例占全部案例的比例`

验收预期：

- 第 1 条识别为 `catalog_browse`，返回 2025 年讲座精确总数＋分页；
- 第 2 条识别为 `catalog_browse`，返回讲座数、案例数和联合分页，其中案例年份按来源讲座日期；
- 第 3 条识别为 `semantic_search`，展示需求总结、匹配理由以及最多 20 条相关讲座和案例；
- 第 4 条识别为 `count`，数字由系统确定性计算；
- 第 5 条识别为 `analysis_required`，不根据有限搜索结果直接计算比例，并引导进入分析工作区。

测试只记录结构化结果、Token 用量和安全错误摘要，不记录 API 密钥或模型原始响应。

### 8.4 整仓验收

实现完成后必须运行：

```powershell
pnpm check
pnpm test:integration
```

同时完成知识 Web 与 Worker 的生产构建，并使用真实页面模拟以下流程：创建搜索、等待任务、查看总结、翻页、打开历史结果、查看详情、单条加入工作区、批量勾选、全选当前页、切换页面清空选择、服务端去重和分析工作区分流。

不得通过放宽既有安全 Schema、知识金标阈值、账号授权或工作区资料版本约束来使测试通过。

## 9. 实施顺序

1. 扩展智能搜索意图、计划和结果契约。
2. 为案例索引增加 `source_date`，完成数据派生和索引原子重建。
3. 实现确定性目录浏览、计数、联合去重和稳定分页。
4. 调整语义搜索候选召回、白名单重排和安全回退。
5. 增加分析工作区分流和建议资料范围。
6. 建立版本化冻结结果表和旧搜索历史兼容读取。
7. 更新搜索总结、结果卡、分页和历史页面，同时保留单条及批量加入工作区能力。
8. 补齐单元测试、集成测试、五条真实 DeepSeek 测试和页面功能模拟。
9. 实施阶段再同步更新 `project_design.md` 与 `AGENTS.md`；本计划写入阶段不修改这两个文件。

## 10. 默认约定与非目标

- 目录浏览和计数追求完整、确定、可分页；语义搜索追求相关性，不承诺穷尽全部资料。
- 默认每页20条、最大50条；批量全选仅作用于当前页。
- 语义搜索最多60条候选和20条结果，只有语义搜索进入 DeepSeek 候选重排。
- 简单数量问题在搜索模块中完成；比例、趋势、复杂比较和因果分析进入分析工作区。
- 案例年份按来源讲座日期解释，并在界面中明确标注。
- 本阶段不开放模型直接访问数据库、Meilisearch 管理密钥或完整未筛选知识库。
- 本阶段不取消普通关键词搜索，也不改变已经实现的单条加入工作区、批量勾选、全选当前页和服务端去重行为。
