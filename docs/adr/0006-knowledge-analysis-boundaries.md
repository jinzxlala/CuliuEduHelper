# ADR 0006：智能搜索与知识分析边界

- 状态：已接受
- 日期：2026-08-05
- 适用范围：`docs/dev_plan_stage3.md`

## 背景

知识系统已经具备普通关键词搜索、版本化讲座与案例、内部账号和独立 Worker。第三阶段需要增加有界智能搜索、可分享分析工作区、多对话和单页分析报告，同时继续保证 PostgreSQL 是正式版本来源、Meilisearch 只是可重建索引，且模型不能扩大权限或创造知识引用。

## 决策

1. 智能搜索、分析对话和报告继续作为普通 TypeScript 领域模块和 BullMQ 任务实现，不引入通用 Agent 框架、动态 Skill Runtime 或独立向量数据库。
2. 所有长任务只携带运行 ID、冻结快照 ID/hash、授权上下文和版本信息；Worker 从 PostgreSQL 重新读取正文并复验当前账号、工作区成员关系和冻结来源。
3. 工作区只允许显式成员访问，角色固定为 `owner`、`editor`、`viewer`。审计员只能作为 `viewer`，服务账号不能成为成员，管理员不因全局角色自动获得工作区正文权限。
4. 加入工作区的讲座和案例冻结具体知识批次、来源 ID 与内容哈希。知识库发布新批次时保留原引用，只提示用户主动创建替代版本。
5. 同一工作区可以包含多个对话，但模型任务只读取当前对话和当前工作区资料，不自动读取其他对话。
6. 报告统计由确定性 TypeScript 代码计算。模型只生成结构化叙述、分类和图表配置，不执行 SQL、JavaScript、Python 或任意工具代码。
7. 报告生成交互版和静态归档版两个不可变对象。交互版只运行仓库内固定、版本化、经过测试并由 CSP 哈希放行的脚本；模型和用户都不能提供脚本。
8. 普通关键词搜索必须在 DeepSeek、Worker或嵌入模型不可用时继续工作。

## 数据与状态约束

- 工作区最多 100 个当前资料版本和 50 个对话；
- 对话消息追加写入，不允许覆盖或删除；
- 成功或失败的模型运行与报告进入终态后不可修改或删除；
- 已移除的工作区资料保留历史，更新通过 `supersedes_source_id` 追加新版本；
- 来源必须引用已经发布的知识批次以及该批次中的讲座或案例；
- 报告对象路径只能位于 `knowledge/reports/`，交互版和静态版分别保存哈希；
- 浏览器不接收数据库、Meilisearch、对象存储或模型密钥。

## 后果

该设计增加了版本表、状态机和双版本报告的实现量，但使旧分析可复现、跨工作区访问可确定性拒绝，也让模型故障不会破坏普通搜索。若未来确实需要更多交互控件，只能扩展固定模板和允许的结构化报告 Schema，不能放开模型生成脚本。
