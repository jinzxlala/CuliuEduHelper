# ADR 0003：知识来源清单与证据映射

- 状态：已接受
- 日期：2026-08-01
- 范围：阶段 1“匿名知识搜索”的来源清单子模块

## 背景

阶段 1 需要导入 48 份讲座分析稿及配套逐字稿，但正式导入前必须先证明来源一一对应、内容没有静默漂移，并明确哪些文件能进入哪个索引。分析稿与逐字稿的隐私等级不同；如果直接把全部原始字段写入 Meilisearch，源 JSON 中的绝对路径和逐字稿中的身份信息可能形成新的隐私副本。

## 决策

1. 为每场讲座建立由文件名日期和标题部分确定的 `source_key`，再由 `source_key` 的 SHA-256 派生稳定的 `lecture_id`。
2. 每个讲座包必须恰好包含分析 Markdown、清洗后逐字稿 JSON、QA JSON、SRT 和带时间戳 TXT 五种角色；按原始字节计算 SHA-256，并以角色与哈希生成讲座包哈希和语料库哈希。
3. 清单只保存逻辑相对路径、哈希、大小、标题、章节名和校验统计，不保存正文、外部物理根路径或源 JSON 中的绝对路径。
4. 分析 Markdown 是 `lectures` 和 `cases` 的主要来源；案例时间戳需要逐字稿 JSON／SRT 佐证。
5. 清洗后逐字稿 JSON 只有经过隐私复核和匿名化门禁后才可映射到 `transcript_segments`。SRT、TXT 和 QA JSON 是校验材料，不直接进入索引。
6. 原始来源始终只读。本模块不执行数据库迁移、不写 PostgreSQL、不写 Meilisearch，也不启动 Worker 导入任务。
7. QA JSON 的 `source_sha256` 指向清洗前 ASR JSON，只校验其格式，不错误地与清洗后 JSON 的当前文件哈希比较；QA 的句子数和实际文本变更数仍须与清洗后 JSON 一致。
8. 单场 JSON、SRT 和 TXT 的句子数、文本和起止时间必须一致；分析稿必须具备基础信息、摘要、趋势、案例、AI+、失败、关键原话、行动建议和证据边界九类语义章节。

## 结果

- 后续导入器可以把清单作为确定性的输入门禁，并按内容哈希实现幂等与变更检测。
- 清单存在不代表逐字稿已获准索引；隐私门禁仍是独立且不可跳过的步骤。
- 文件名、来源角色或正文发生变化时，生成器会产生明确失败或新的内容哈希，而不是静默沿用旧映射。
- Meilisearch 仍是可重建索引，正式来源关系和版本记录将在后续 Worker 导入模块中写入 PostgreSQL。
